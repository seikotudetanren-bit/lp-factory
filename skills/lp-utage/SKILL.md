# lp-utage — UTAGE への設置と計測

根拠は UTAGE 公式ヘルプ（2026-10-21 確認）。画面は変わることがあるので、食い違ったら実画面を優先し、このスキルを直す。

- [HTMLでファネルページを作成する](https://help.utage-system.com/archives/25558)
- [ページ設定（カスタムJS・CSS）](https://help.utage-system.com/archives/4489)
- [登録経路機能（LINE）](https://help.utage-system.com/archives/6101)

## 前提（brief を作る段階で確認する）

| 確認すること | なぜ |
|---|---|
| その院の LINE 公式アカウントが UTAGE と連携済みか | 登録経路（LINE）は連携が前提。未連携なら登録経路URLを発行できない |
| このLP専用の登録経路を発行したか | 院の共通URLだと、このLPから何人登録したかが分からない |
| 登録経路の管理名称の付け方 | 案件をまたいで集計するので揃える。`LP_<院>_<主訴>_<YYYY-MM>` |

### 登録経路の発行（人の作業、またはブラウザ操作）

1. 上メニュー【メール・LINE配信】→ 配信アカウント → シナリオを選ぶ
2. 右メニュー → シナリオ設定 →【登録経路】→『追加』
3. 『管理名称』に `line_route_name`、『種類』は `LINE`、広告連携は「連携しない」
4. 発行されたURLを `brief.md` の `line_route_url` に入れる

> 登録経路の情報は、シナリオ遷移すると引き継がれない（公式ヘルプの注意事項）。
> LP → LINE登録 の1段なら問題ない。登録後に別シナリオへ移す設計にするときは、ファネル側の登録経路を検討する。

## HTMLページで使えないもの

ページ全体をHTMLで作ると、UTAGE の「決済フォーム」「イベント申込フォーム」などのページ要素は使えない。
このプラグインのLPは LINE 登録への誘導だけなので影響はない。**フォームが必要な案件は、この手順の対象外**。

## 設置手順

1. 設置前に、ローカルで最終検証を通しておく:

   ```bash
   python3 "$PLUGIN_ROOT/scripts/validate_lp.py" lp-projects/<slug>/index.html --mode <mode> --brief lp-projects/<slug>/brief.md
   ```

2. 【ファネル】→ ファネル一覧 →「+追加」→ テンプレート【空白のファネル（HTML）】→「このファネルを追加する」
   - 院ごとのファネルを既に作ってあるなら、そのファネルのページ一覧 →「＋追加」→ ファネルステップ →「＋ページ追加」→【HTMLから追加】でもよい
3. ページ編集画面の【HTML】欄に `index.html` の**全文**（`<!doctype html>` から `</html>` まで）を貼る
4. 【管理名称】は `line_route_name` と同じにする（UTAGE の画面と knowledge の記録を突き合わせやすくするため）
5. 保存 →「プレビュー」で確認する
6. 公開URLを控える

### ブラウザ操作で設置するとき

UTAGE はユーザーのログイン済みセッションで操作するので、Claude in Chrome を使う（`anthropic-skills:chrome-browser` を先に読む）。

- **ファネルの追加・保存・公開はそれぞれ外部に変更が残る操作。1つずつユーザーの確認を取ってから押す**
- HTML欄に貼るときは、全文を1文字ずつ打たない。テキストエリアの値を設定してから、入力イベントを発火させる
- ログイン情報の入力は行わない。ログインが切れていたらユーザーに頼む

## 公開後の確認

1. 公開URLをスマホ幅（375px）で開き、ファーストビュー・固定CTA・最後のCTAが表示されるか見る
2. すべての主CTAのリンク先が `line_route_url` かを、ページのリンクを読んで確認する（**実際に友だち追加はしない**）
3. UTAGE が独自のタグを差し込むことがあるので、公開版で `validate_lp.py` が外部読み込みを指摘しても、それが UTAGE 由来なら問題ない。自分が書いたHTMLに由来するものだけ直す
4. `/lp-record <slug> <公開版を保存したファイル> <公開URL>` で記録する

## 成果の取り込み（段階2）

UTAGE の【登録経路分析】（右メニュー → シナリオ設定 → 登録経路分析）で、その経路の数値を読む。

| UTAGE の表示 | 意味 | 取り込み先 |
|---|---|---|
| アクセス数(PV) | 登録経路URLへのアクセス総数 ＝ **CTAのクリック数**に近い | `--route-pv` |
| アクセス数(UU) | 同じく重複なし（IPアドレス基準） | `--route-uu` |
| 登録数 | その経路からのLINE登録数 | `--line-adds` |

> **注意: ここで取れる PV/UU は「LPの表示数」ではなく「登録経路URLへのアクセス数」。**
> LP自体の表示数は、ファネルの分析画面（ページのアクセス数）から別に読む（`--lp-pv`）。
> 「LP表示 → CTAクリック → LINE登録」の3段がそろうと、どこで落ちているかが分かる。
> UU は IP 基準なので、同じ回線の複数端末は1と数えられる。

`/lp-results` から `record_results.py` で knowledge に記録する。**月に1回、同じ日付で**取り込むと比較しやすい。
